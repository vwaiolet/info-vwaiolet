### 대용량 트래픽 대응 정량적 성과

- 체감 응답 지연 시간의 혁신적 단축: 동기식 멀티모달 토큰 생성 방식에서 발생하던 전량 버퍼링 대기 현상을 비동기 청크 단위 스트리밍 아키텍처로 전면 개편하여, 대규모 동시 요청 환경에서 첫 토큰 수신 속도를 보장하고 서버 가용 메모리 점유율을 대폭 낮췄음
- 디스크 및 네트워크 I/O 부하 제거: Google Vertex AI 연동 시 발생하는 OAuth 2.0 액세스 토큰 발급 구조에 @lru_cache 기반 인메모리 자격 증명 캐싱 메커니즘을 결합하여, 인증 파일 I/O 및 구글 인증 서버로의 중복 요청 아웃바운드 트래픽을 차단했음
- 커넥션 풀 고갈 방지 및 커밋 무결성 확보: 고빈도 세션 및 대량 학습 로그 적재 시 병목을 방지하기 위해 정규화된 스키마에 인덱스를 전략적으로 배치하고, 커밋 실패 시 즉각적인 db.rollback() 처리를 관장하는 방어적 컨텍스트 매니지먼트를 내재화했음

### 동시성 최적화 경험

- 독해, 문법, 작문, 청취 등 멀티모달 서비스 특성상 대량의 유저가 동시에 접속하여 LLM(Vertex AI), TTS(AWS Polly), Vision(Stability AI) 인프라를 복합적으로 호출하는 상황이었음. 동기식 백엔드 아키텍처 모델을 채택할 경우, 외부 API 응답을 대기하는 동안 ASGI 워커 스레드가 고갈되어 후속 유저의 요청이 타임아웃 되는 치명적인 아키텍처 한계가 존재했음
- 외부 서비스의 대기 지연이 시스템 전체로 전파되는 블로킹 현상을 원천 배포 단계에서 차단하고, 동시 접속자에게 끊김 없는 데이터 스트림을 실시간으로 중계할 수 있는 비동기 오케스트레이션 파이프라인을 구축해야 했음
- FastAPI의 네이티브 ASGI 이벤트 루프와 Vertex AI의 generate_content_async(stream=True) 엔진을 연동한 비동기 제네레이터 아키텍처를 전면 도입했음
- 자체 엔진 컴포넌트를 설계하여 대용량 컨텍스트가 포함된 원문 데이터를 메모리에 일시 적재하지 않고, 수신되는 즉시 StreamingResponse를 통해 클라이언트로 청크 전송 처리했음
- 오디오 데이터 파이프라인 엔진과 비전 생성 인프라 호출 시 비동기 I/O 바인딩 패턴을 적용하여, 네트워크 대기 시간 동안 이벤트 루프가 다른 유저의 웹 요청 트래픽을 동시 처리하도록 자원 효율성을 극대화했음
- 외부 대규모 모델 연동으로 인한 스레드 락 현상을 완벽히 해결했으며, 다중 유저 트래픽 급증 시에도 타임아웃 발생률을 제로에 가깝게 통제하는 초고성능 백엔드 엔드포인트를 확보했음

### 비동기 AI 파이프라인 및 병목 최적화 아키텍처

**청크 단위의 비동기 스트리밍 제어 프로토콜**       
대용량 트래픽의 핵심은 메모리 자원 관리임. 수천 개의 커넥션이 긴 문장의 AI 피드백을 동기식으로 대기할 경우 서버 메모리는 임계치에 도달함. 이를 해결하기 위해 백엔드 코어 단에 텍스트 스트리밍 제어 모듈을 적용했음. 문자열 종단 마커를 탐지하는 비동기 파싱 로직을 결합하여, 네트워크 연결이 유지되는 동안 유저 이탈을 방지하고 유연하게 대역폭을 나누어 쓰는 고효율 통신 규격을 정착시킴

**인메모리 인증 캐싱을 통한 자격증명 오버헤드 최소화**      
GCP Vertex AI API 통신 시 서비스 계정 크레덴셜 정보를 매번 디스크에서 파싱하는 행위는 고트래픽 상황에서 심각한 디스크 I/O 스파이크를 발생시킴. 정적 토큰 관리 구조를 구현하고, 유효기간 내의 액세스 토큰을 메모리에 유지하는 방식을 도입함으로써 인증 오버헤드를 물리적으로 생략하고 내부 API 라우팅 레이턴시를 획득했음

| :--- | :--- | :--- |
| FastAPI (ASGI) | Node.js 및 Go와 대등한 고성능 비동기 이벤트 루프를 Python 환경에서 네이티브로 활용 가능하여 선정 | 스레드 생성 오버헤드 없이 단일 프로세스 내에서 수만개의 동시 I/O 커넥션을 효율적으로 스케줄링 |
