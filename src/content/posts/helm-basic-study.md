### 1. 헬름 차트(Helm Chart)란?

- 정의: 쿠버네티스용 애플리케이션 패키지임 (리눅스의 apt, Node.js의 npm 같은 역할을 쿠버네티스에서는 헬름이 수행함)
- 구조: 실제 쿠버네티스 리소스의 뼈대가 되는 템플릿 파일들(templates/)과 여기에 주입할 동적 변수들이 담긴 설정 파일(values.yaml)로 구성됨

### 2. 도커 컴포즈와의 비교

- 도커 파일(Dockerfile)과의 비교: 도커 파일은 단일 이미지를 굽는 레시피이므로 헬름 차트와는 다름
- 도커 컴포즈(docker-compose)와의 비교: 헬름 차트는 도커 컴포즈와 매우 유사함. 여러 컨테이너(서비스, DB, 네트워크 등)를 하나로 묶어서 동시에 띄우고 내리기 때문임
- 차이점: 헬름 차트는 단순 묶음을 넘어 동적 변수 주입(템플릿), 배포 버전 관리 및 롤백, 오픈소스 앱 스토어(Artifact Hub) 기능까지 갖춘 스마트한 쿠버네티스용 도커 컴포즈임

### 3. 순수 YAML 배포 vs 헬름 차트 배포

| 비교 항목 | 순수 YAML (kubectl apply) | 헬름 차트 (helm install) |
| :--- | :--- | :--- |
| 작성 방식 | 고정된 정적(Static) 파일 | 조건문/반복문이 가능한 동적(Dynamic) 템플릿 |
| 환경 분리 (Dev/Prod) | 환경마다 YAML 파일을 복사해서 따로 관리 (중복 발생) | 뼈대 템플릿은 하나만 두고, values.yaml 파일만 바꿔서 재사용 |
| 리소스 관리 | Pod, Service, Ingress 등을 개별 파일로 직접 관리 | 릴리스(Release)라는 하나의 패키지 단위로 묶어서 일괄 관리 |
| 설치 및 삭제 | 파일마다 일일이 명령어를 실행해야 함 | helm install / uninstall 명령어로 한 번에 해결 |
| 버전 관리 및 롤백 | 수동으로 이전 YAML 파일을 찾아 재배포 해야 함 | helm rollback 명령어 하나로 이전 상태 복구 가능 |
| 외부 앱 설치 | 인터넷에서 복잡한 설정을 직접 찾아 한 땀 한 땀 구현 | Artifact Hub에서 검증된 차트를 가져와 명령어 한 줄로 즉시 구축 |

```text
[한 줄 요약]
순수 YAML이 각 부품을 일일이 조립하는 수동 조립 키트라면, 헬름 차트는 원하는 옵션(values.yaml)만 선택하면 알아서 맞춤 조립되고 문제가 생기면 되돌리기(롤백)까지 가능한 원클릭 배포 패키지임
```
